CHANNELKHAN COOLIFY SETUP

These files are a starting deployment, not a verified live store. Both Compose files pass Docker Compose validation. A full image build was not run because Docker Desktop is not running locally.

1. Extract this ZIP. Upload its CONTENTS to the root of esakhan0/channelkhan-shop using GitHub > Add file > Upload files. Preserve apps/backend/medusa-config.ts at that exact path and include the hidden .dockerignore file. Commit the changes. No secrets are included.

2. In Coolify create a new Application from your GitHub repository. Use Docker Compose, root base directory /, and Compose location /docker-compose.yml. This is a repository-backed Application, not Docker Compose Empty.

3. Set POSTGRES_PASSWORD, JWT_SECRET and COOKIE_SECRET in Coolify. Use three different long random values. Use only hexadecimal characters for the database password to avoid URL escaping. This NEW application creates a NEW database volume and does not migrate existing data. Keep the previous service/volume until you have confirmed nothing needs preserving.

4. Assign BOTH https://api.channelkhan.com and https://shopadmin.channelkhan.com to the medusa service on container port 9000 using Coolify's domain settings. DNS for these domains must point to your server. Deploy the backend. Check https://api.channelkhan.com/health returns OK. Admin is https://shopadmin.channelkhan.com/app, not the domain root.

5. In Coolify's medusa container terminal the working directory should be /server/apps/backend/.medusa/server. Create your admin account using:
pnpm exec medusa user -e YOUR_EMAIL -p YOUR_CHOSEN_PASSWORD
Use your own email/password privately. Never commit them to GitHub.

6. Sign into Admin. This starter's initial migration creates demo store data and a default publishable API key. Under Settings > Publishable API Keys, copy the default key and ensure it is associated with your sales channel. Review demo products, currencies, inventory, shipping and regions before selling. It defaults to demo inventory and EUR/USD, not a configured UK business.

7. Create a SECOND Coolify GitHub Application from the SAME repository, also Docker Compose, but use /docker-compose.storefront.yml. Set MEDUSA_PUBLISHABLE_KEY to the key from step 6. STRIPE_PUBLISHABLE_KEY is optional at this stage. Assign https://shop.channelkhan.com to storefront on port 8000. Deploy AFTER the backend is reachable. Changes to public keys/URLs require rebuilding the storefront.

8. Test browsing, sign-in, cart, ordering and persistence after redeploy. Stripe is NOT configured in the backend by these files. Do not accept real orders yet. Email delivery, Stripe/webhooks, backups, monitoring and production Redis-backed modules still need setup. This initial single-instance backend uses shared worker mode; do not scale it to multiple replicas without configuring the production modules. Uploaded files use a local persistent volume and need backups.

If a deployment fails, share the build/startup error without secret values. Do not delete database volumes to troubleshoot.

Optional: the repository recommends Medusa's agent skills and documentation MCP for further development. Those integrations were unavailable here; official Medusa documentation was used instead.
